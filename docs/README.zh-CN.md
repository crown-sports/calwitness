# CalWitness：检查日历迁移前后的日程漂移

把迁移前后的两个 ICS 文件放在本地，CalWitness 会在明确的时间窗口内比较日程实例：
有没有丢失、新增、重复、移动或时长变化。它不连接日历账户、不上传或修改文件，
也不以一次有限窗口检查证明整份日历完全一致。

[English guide](report.md)

## 安装和运行

在项目源码目录中，使用 Python 3.10 或以上版本：

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install .
```

Windows PowerShell 使用 `.venv\Scripts\Activate.ps1` 激活环境。
安装依赖可能需要网络；安装后的 ICS 比较过程离线运行。

```sh
calwitness compare before.ics after.ics --from 2026-03-01 --until 2026-04-01 --json report.json --html report.html
```

用浏览器打开 `report.html`。报告是一个独立 HTML 文件，不加载脚本、远程字体、外部资源或跟踪。
可展开匹配依据、折叠差异分组，也可用浏览器查找功能定位实例键或问题代码。
HTML 与 JSON 来自同一次比较，HTML 层不会重新展开日程或猜测匹配。

| 退出码 | 含义 |
| --- | --- |
| `0` | 比较完整，窗口内未发现日程实例差异。 |
| `1` | 比较完整，发现差异。对有变化的迁移结果，这是正常结果，并非安装失败。 |
| `2` | 比较不完整、输入无效/不受支持，或命令、输出文件发生错误。请看问题列表或错误消息。 |

`--json -` 可将 JSON 写到标准输出。`--max-occurrences N` 与 `--timeout SECONDS`
限制展开量和耗时；达到限制会明确标记不完整，不会把截断结果标成一致。
保守的候选工作量限制可能在最终实例数达到上限之前拒绝过密或存在时间很长的规则，
而不是先进行昂贵展开后才截断结果。
用 `calwitness compare --help` 查看当前安装版本的参数与默认值。

## 先试人工构造的迁移样本

仓库示例不含账户数据，可直接运行：

```sh
calwitness compare examples/before.ics examples/after.ics --from 2026-10-01 --until 2026-11-01 --json demo.json --html demo.html
```

预期退出码 `1`：**新增 2、移除 1、移动 1、时长改变 2、未变 1**。
迁移后的示例故意漏掉重复日程的 `EXDATE`，使已排除的一次日程重新出现；又漏掉单次例外覆盖，
使该实例回到系列原时间。另有一小时变两小时、全天一天变两天，以及不同 UID 的单次事件替换。
打开六张差异卡可逐项核对。这是人工测试样本，不是对某个真实日历服务的故障测量。

重复日程跨越 2026 年 10 月的时钟调整。再比较等价时区写法：

```sh
calwitness compare examples/before.ics examples/equivalent.ics --from 2026-10-01 --until 2026-11-01 --html equivalent.html
```

预期退出码 `0`：示例中的柏林/巴黎写法在此窗口内对应相同的日程实例，不能据此把任意时区名称互换。

[静态演示](https://crown-sports.github.io/calwitness/) 包含有差异的报告，以及重复身份导致不完整的报告。
安装本源码后运行 `python docs/demo/build.py` 可重新生成页面。构建器调用真实比较 API，
并断言预期状态与计数，不手写结果，也不接受私人日历路径。不同构建环境的运行版本记录可能不同。

## 按顺序读报告

先看结论和窗口。起点包含、终点不包含，即 `[start,end)`。当实例在任一输入中的开始时间
落入窗口时，它会被选中；另一侧已匹配的实例可以在窗口外，因此能展示跨边界的移动。
如果两侧开始时间都在窗口外，仅持续时间与窗口重叠，则不属于本次检查。

然后看 **Issues that affect interpretation**。遇到重复身份、未知时区、不受支持的递归规则
或展开失败，报告会显示 **Comparison incomplete**。输入侧有问题时会停止报告差异，
避免把展开失败误判为大批日程丢失。此时即使显示 0 项差异，也不能认为迁移成功。

再看前后对照：

| 英文标签 | 含义 |
| --- | --- |
| Removed | 迁移前的实例没有找到迁移后的对应项；不是对日历所有日期作全局判断。 |
| Added | 迁移后的实例没有找到迁移前的对应项。UID 被重写时，可能表现为一删一增。 |
| Moved | 身份已匹配，开始时间改变。 |
| Duration changed | 身份已匹配，持续时长改变。 |
| Moved and duration changed | 同一实例的开始时间和时长都改变，只在这一组计一次。 |
| Unchanged | 已匹配的开始时间与时长一致；不表示标题、提醒等其他属性一致。 |

每张卡展示前后开始、结束、时长、源组件位置和是否为单次例外覆盖。全天日程保留日期，结束日期
不包含在内；带时区的时间统一为可比较的时间点。展开 **Identity and matching evidence**
可查看 UID 摘要、完整实例键和匹配依据，报告不展示原始 UID。

匹配以稳定的 UID 和完整的递归实例身份为准，不会因为标题相似、时间接近就擅自配对。
一个被移动的单次例外应保留原来的 `RECURRENCE-ID`；新的 `DTSTART` 不是它的新身份。
如果导出程序重写 UID，应单独调查原因，不能把模糊匹配当成正确迁移的证据。
把非重复事件改成 `RRULE:FREQ=DAILY;COUNT=1` 也会改变身份类型：即使时间相同，
仍报告为移除加新增，不跨类型猜测它们是同一次日程。

最后查看 **Evidence and scope** 中的源文件字节数、SHA-256、源事件数、用于匹配而保留的实例数、
完整性和运行版本。源实例数可能包含窗口外的非重复事件、单次例外和展开余量，并非窗口内差异数。
校验和用于确认比较的是哪两个本地文件；`VEVENT[2]` 一类位置可帮助
在原文件中定位组件，不需要把日程正文放进报告。
输入不完整时，源事件数和实例数显示为尚未确定，避免把中止展开误读为空日历。

## 时区与首版边界

不同的时区写法如果代表同一个时间点，不算漂移。错误时区使实际时间点改变时，会表现为移动；
工具不会仅凭这一结果断言原因就是时区。无法确定的时间解释会报告问题，而不是猜一个时区。

没有时区的浮动时间，需要你明确知道它的含义后再指定：

```sh
calwitness compare before.ics after.ics --from 2026-03-01 --until 2026-04-01 --floating-zone Asia/Shanghai --html report.html
```

该假设对两侧输入都生效，并记录在报告中。工具不会仅凭 `X-WR-TIMEZONE` 偷偷解释浮动时间。
明确写出或递归生成的本地时间，只要存在歧义或该时间不存在，比较都会标记不完整。
工具不会猜测偏移量，也不会静默跳过一个实例后声称保留了 `COUNT` 的含义。

首版覆盖所支持规则子集中的按天、周、月、年重复，日期/日期时间形式的 `RDATE`、`EXDATE`
以及单次例外。不支持的小时级规则、`RDATE` 时间段、`RECURRENCE-ID;RANGE=...` 等会明确报出。
不受支持的组件、方法和时区定义也会报问题。有限窗口检查不等于对未来所有年份或全部 ICS 功能的保证。

常见问题代码：`DUPLICATE_IDENTITY` 表示多个相同组件争用同一身份；`AMBIGUOUS_IDENTITY`
或 `AMBIGUOUS_OCCURRENCE` 表示存在冲突候选，无法唯一配对；`MISSING_UID`、
`ORPHAN_OVERRIDE` 表示缺少身份或主事件；`FLOATING_TIME`、`UNKNOWN_TIMEZONE`、
`AMBIGUOUS_LOCAL_TIME` 表示时间解释有问题；`EXPANSION_LIMIT`、`WORKER_TIMEOUT`
表示未在限制内完成。先检查原始文件，再决定是否修正导出过程。

## 隐私与复现

报告省略原始 UID、标题、描述、参会人、日历正文和源文件名，但仍有实例日期/时间、
结构位置、源文件校验和、UID 摘要。这是减少数据暴露，不是匿名化；稳定摘要可以关联记录，
日程时间也可能泄露私人信息。分享前请自行检查。所有值均按文本转义，不会成为可执行 HTML、
脚本、链接或网络请求。

私下保留两份原始文件、JSON 报告、时间窗口和浮动时区假设。报告会记录依赖与运行环境版本，
依赖更新后结果变化时可据此复现。标题、提醒、参会人等未比较的属性，仍需在原始日历中另行验证。
